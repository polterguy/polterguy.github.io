## This reference was not written. It was asked for.

Every page in this section is generated, and what it is generated from is not the source code but the **running system**. Each slot in Magic Cloud carries its own name, description, arguments and return value as metadata, and Hyperlambda can read that metadata at runtime. Once a week a GitHub Actions workflow asks for it, receives **408 slots**, and renders the pages you are reading. Nobody parses source files, scrapes anything or keeps a second copy that can go stale.

### Why this is possible: homoiconicity

Hyperlambda is homoiconic. A program is a tree of nodes, and a tree of nodes is also the data structure the program works on. A slot is an ordinary node, and asking about slots is an ordinary function call: **[vocabulary]** lists their names, **[slot.description]** returns what one of them does, **[slot.signature]** returns its contract as a tree, and **[lambda2hyper]** writes any tree back as Hyperlambda text. Meta programming is not a library you import here, it is what the language does by default. This documentation is a Hyperlambda program whose input is the definition of Hyperlambda itself.

### The code that produced this reference

This is the complete Hyperlambda file behind the endpoint the pipeline calls. This is dogfooding in its purest form: the language documents itself with its own code.

```hyperlambda
// Executable Hyperlambda file that lists every slot registered in the system and, for each slot, returns its name, its description and its signature. Returns a JSON array of objects, each with fields name (string), description (string) and signature (the slot's signature as nodes, so it converts to nested JSON). Open to everybody, since it only reads metadata that is public in the open source code and runs no code supplied by the caller. Callers are throttled to 10 requests per 60 seconds per IP address, and everybody together to 60 requests per 60 seconds.
.arguments
execution.throttle.create:docs-slots.ip
   limit:int:10
   window:int:60
   per:ip
execution.throttle.create:docs-slots.global
   limit:int:60
   window:int:60
   per:global
execution.throttle:docs-slots.ip
execution.throttle:docs-slots.global
vocabulary
.result
for-each:x:@vocabulary/*
   slot.description:x:@.dp/#
   slot.signature:x:@.dp/#
   /*
    * The signature is returned as nodes, which Magic converts to nested JSON. A constraint is
    * named after its kind and can occur more than once, which JSON cannot hold as a key, so each
    * constraint, at any depth, becomes an unnamed node carrying its kind as a child.
    */
   for-each:x:@slot.signature/**/constraints/*
      get-name:x:@.dp/#
      unwrap:x:+/*/*
      add:x:@.dp/#
         .
            kind:x:@get-name
      set-name:x:@.dp/#
         .:.
   .entry
      .
         name:x:@.dp/#
         description:x:@slot.description
         signature
   unwrap:x:@.entry/*/*
   add:x:@.entry/*/*/signature
      get-nodes:x:@slot.signature/*
   add:x:@.result
      get-nodes:x:@.entry/*
return-nodes:x:@.result/*
```

It begins with two throttles, one per IP address and one for everybody together, and has no authentication, since there is nothing to protect: it reads metadata that is public in the open source code and runs nothing a caller sends. Everything after that is slots, and nothing else. It lists the compiled slots, reads the description and the signature of each, and returns the signature as **nodes**. Magic turns nodes into JSON by itself, since a tree of nodes already is a tree of JSON objects, so there is no serialising step, no text format to agree on and nothing to parse. One detail shows how it works. A constraint is named after its kind and can occur more than once, which a JSON object cannot hold as a key, so the loop in the middle renames every constraint, at any depth, to an unnamed node with its kind as a child, using the `**` selector to reach them all in one expression. Magic then writes them as a list. A Python script renders the result as markdown.

### Get the whole reference yourself

The endpoint above is public. There is no account, no key and no secret. To protect the server it is throttled to **10 requests per 60 seconds per IP address**, and to **60 per 60 seconds** for everybody together, and beyond that it answers `429`. The answer is about 460 KB, so keep a copy rather than asking again.

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots
```

It returns a JSON array with one object per slot, with the fields `name`, `description` and `signature`. The signature is the contract of the slot as nested JSON: `input` is the value the slot takes, `children` are its arguments, `constraints` are the rules between them, `scope` says where it can be used, and `output` is what it returns. Arguments without a name, because they are positional, come as a list. With `jq` you can ask it questions.

#### List every slot name

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots | jq -r '.[].name'
```

#### Get the description of one slot

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots | jq -r '.[] | select(.name == "strings.concat") | .description'
```

#### Get the full signature of one slot

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots | jq '.[] | select(.name == "data.read") | .signature'
```

#### List the arguments of a slot

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots | jq -r '.[] | select(.name == "data.create") | .signature.children | keys[]'
```

#### List only the required arguments of a slot

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots | jq -r '.[] | select(.name == "data.create") | .signature.children | to_entries[] | select(.value.required == true) | .key'
```

#### Find the slots whose description mentions something

```bash
curl -s https://hyperlambda.dev/magic/modules/docs/slots | jq -r '.[] | select((.description // "") | test("rows")) | .name'
```

The public sandbox below sees fewer slots than this endpoint. It runs **your** code, so it can only describe the **53 slots** it is itself allowed to call. A slot can only be described by code that is allowed to call it, so a sandbox that described everything could also run everything. Use the endpoint for the whole language, and the sandbox to experiment.

### The public sandbox

Anybody can send Hyperlambda to **`POST https://hyperlambda.dev/magic/modules/docs/playground`**, with no account and no key. It is rate limited to **30 requests per 60 seconds** per IP address, stops after **20 seconds**, and accepts up to **4000 characters**. Every slot your code uses is checked against the whitelist before anything runs, so code that touches files, databases, the network or configuration is rejected rather than executed. Send `{"describe": true}` to get the exact vocabulary, limits and timeout without running anything. AI agents can find it in [/.well-known/hyperlambda-agent](https://hyperlambda.dev/.well-known/hyperlambda-agent), and it is yours to experiment with.

Save any example below as `example.hl` and send it like this.

```bash
jq -Rs '{hyperlambda: .}' example.hl | curl -s https://hyperlambda.dev/magic/modules/docs/playground \
  -H "Content-Type: application/json" -d @-
```

#### List the slot names

[vocabulary] returns the slots you are allowed to see. With a prefix it filters, so `vocabulary:strings.` returns only the string slots.

```hyperlambda
vocabulary:strings.
return-nodes:x:@vocabulary/*
```

#### Get one description

```hyperlambda
slot.description:strings.concat
return-value:x:@slot.description
```

Returns `Concatenates strings`.

#### Get every description

The same loop the full reference uses, without the signature.

```hyperlambda
vocabulary
.result
for-each:x:@vocabulary/*
   slot.description:x:@.dp/#
   .entry
      .
         name:x:@.dp/#
         description:x:@slot.description
   unwrap:x:@.entry/*/*
   add:x:@.result
      get-nodes:x:@.entry/*
return-nodes:x:@.result/*
```

#### Get one signature as Hyperlambda

[slot.signature] returns a tree, and [lambda2hyper] writes any tree back as Hyperlambda text. [lambda2json] would give you JSON instead.

```hyperlambda
slot.signature:convert
lambda2hyper:x:@slot.signature/*
return-value:x:@lambda2hyper
```

#### Get only the arguments of a slot

```hyperlambda
slot.signature:convert
.result
for-each:x:@slot.signature/*/children/*
   get-name:x:@.dp/#
   .entry
      .
         name:x:@get-name
         type:x:@.dp/#/*/type
         required:x:@.dp/#/*/required
         description:x:@.dp/#/*/description
   unwrap:x:@.entry/*/*
   add:x:@.result
      get-nodes:x:@.entry/*
return-nodes:x:@.result/*
```

Returns `[{"name": "type", "type": "string", "required": true, "description": "Target Hyperlambda type name"}]`.

#### Get only the required arguments

```hyperlambda
slot.signature:convert
.result
for-each:x:@slot.signature/*/children/*
   if
      eq:x:@.dp/#/*/required
         .:bool:true
      .lambda
         get-name:x:@.dp/#
         unwrap:x:+/*/*
         add:x:@.result
            .
               .:x:@get-name
return-nodes:x:@.result/*
```

Returns `["type"]`.

      eq:x:@.bypass

   get-value:x:@.policy/*/return-code

         get-value:x:@.code

         .
            reason
      set-value:x:@.response/*/reason
         get-value:x:@.reason

   .

```yaml
# Keeps the plugin pages and the generated slot reference in sync with Magic Cloud.
#
# Two jobs in one run:
#
# * sync-plugin-docs.py copies each plugin's README.md from the Magic repository,
#   https://github.com/polterguy/magic, to plugins/<plugin>/index.md, adapted for Jekyll.
#   The README is the source of truth.
# * build-slot-reference.py asks a read-only Hyperlambda endpoint on hyperlambda.dev for
#   every compiled slot and renders reference/slots/ from the answer, with each slot's
#   "How to use" guide from the README placed on the slot's own page. The endpoint is
#   public and throttled, so no credentials are needed. Nothing is built, and no source
#   code is parsed.
#
# It runs weekly and on demand, since the Magic repository is a separate project that
# cannot trigger this one without a token. Run it from the Actions tab after a release.
# The commit touches nothing outside plugins/ and reference/, and llms-full.yml rebuilds
# llms-full.txt afterwards because markdown changed.

name: Sync plugin docs and slot reference

on:
  schedule:
    - cron: '0 5 * * 1'
  workflow_dispatch:

permissions:
  contents: write

concurrency:
  group: slot-reference
  cancel-in-progress: true

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/checkout@v4
        with:
          repository: polterguy/magic
          path: magic

      - uses: actions/setup-python@v5
        with:
          python-version: '3.x'

      - name: Copy plugin READMEs
        run: python3 .github/scripts/sync-plugin-docs.py magic

      # Fails, and writes nothing, when the endpoint answers with too few slots.
      - name: Generate slot reference
        run: python3 .github/scripts/build-slot-reference.py --magic magic

      # Fails when a link or anchor is broken, a page is oversized, or README text got lost.
      - name: Lint docs
        run: python3 .github/scripts/lint-docs.py --magic magic

      # Only commit when something actually changed.
      - name: Commit if changed
        run: |
          git add plugins reference
          if git diff --cached --quiet; then
            echo "Nothing changed."
            exit 0
          fi
          git config user.name  "github-actions[bot]"
          git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
          git commit -m "Sync plugin docs and slot reference"
          git push
```
